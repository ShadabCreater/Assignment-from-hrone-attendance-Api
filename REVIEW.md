# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` (lines 72-74) | Always returns HTTP 200 without checking MongoDB connectivity. The contract requires returning 503 if MongoDB is down. | Stop the MongoDB service and request `GET /health`; it returns 200 instead of 503. | Added `db.command("ping")`; if ping raises an exception, return HTTP 503 `{"detail": "Database unavailable"}`. |
| 2 | Startup / Lifecycle (lines 22-23) | No MongoDB indexes are created at application startup. The starter has only default `_id` index, leading to full collection scans (COLLSCAN) on queries. | Inspecting `db.employees.index_information()` or `db.attendance_logs.index_information()` shows only `_id_`. | Added a FastAPI `lifespan` handler that idempotently creates all required unique and compound indexes for fast query execution and data integrity. |
| 3 | `compute_late_minutes()` (lines 33-37) | (1) Ignores timezone by calling `.replace()` on a UTC datetime with IST shift hours. (2) Grace condition `minutes > 10` fails on 09:40:01 (601 seconds): `int(601/60) == 10`, so `10 > 10` is False, returning 0 instead of 10. (3) Does not account for overnight shifts. | For a 09:30 shift, input punch-in at 09:40:01 IST returns 0 instead of 10. | Converted punch-in instant to IST, verified `(punch_in_ist - shift_start_ist).total_seconds() > 600`, and returned floor of elapsed whole minutes since shift_start. |
| 4 | `compute_work_hours()` (lines 40-41) | Uses Python's standard `round()`, which applies banker's rounding (round-half-to-even) instead of the required half-up rounding (R4). | A work duration of 8.125 hours rounds down to 8.12 instead of 8.13. | Used `decimal.Decimal` with `ROUND_HALF_UP` to round strictly half-up to two decimal places. |
| 5 | `compute_overtime()` (lines 44-47) | (1) Ignores the 30-minute minimum qualification threshold (R3). (2) For overnight shifts (`shift_end <= shift_start`), `shift_end` falls on the next calendar day, but starter parses only the start date. | Punching out 15 minutes after shift end returns 15 overtime minutes instead of 0. For overnight shifts (22:00-06:00), punch-out at 06:40 produces negative duration or incorrect days. | Handled overnight shifts by setting shift_end on `date + 1 day`; verified elapsed seconds `>= 1800` (30 min) before returning floor of minutes; otherwise returns 0. |
| 6 | `EmployeeIn` & `create_employee()` (lines 53-61, 78-85) | (1) Lacks schema validation (emp_code regex `^EMP\d{4,6}$`, email pattern, shift time formats). (2) Uses check-then-insert (`find_one` then `insert_one`), creating race conditions under concurrency. (3) `created_at` stored as local naive datetime and returned as ISO string instead of epoch milliseconds. | Sending invalid `emp_code: "abc"` returns 201 instead of 422. Concurrent requests with same `emp_code` result in duplicate inserts or unhandled errors. Response `created_at` is not integer epoch ms. | Added Pydantic field validators; backed uniqueness with unique index on `emp_code` and caught `DuplicateKeyError` to return 409; stored UTC datetime and serialized epoch ms. |
| 7 | `list_employees()` (lines 89-96) | (1) Off-by-one pagination bug: `skip = page * page_size`, which skips the first 20 records when `page=1`. (2) `total` counts the whole collection ignoring the department filter. (3) Lacks sort by `emp_code` ascending. (4) Missing `page` / `page_size` bounds validation. | `GET /employees?page=1` omits items 1-20. Filtering by department returns total count of all employees. `page_size=150` succeeds instead of 422. | Set `skip = (page - 1) * page_size`; passed filter `q` to `count_documents(q)`; added `.sort("emp_code", 1)`; enforced `page >= 1` and `1 <= page_size <= 100`. |
| 8 | `punch_in()` (lines 101, 113) | Missing 404 validation for employee existence. If employee is not found, `emp` is `None`, and line 113 attempts `emp["shift_start"]`, throwing an uncaught `TypeError` and returning HTTP 500. | POST `/attendance/punch-in` with non-existent `emp_code: "EMP9999"` returns HTTP 500 instead of 404. | Added explicit check `if not emp: raise HTTPException(404, "Employee not found")`. |
| 9 | `punch_in()` (lines 104-118) | Check-then-insert race condition. Two concurrent requests for the same employee on the same day both pass `find_one` and attempt insertion. | Sending two simultaneous punch-in requests yields two 201 responses or an unhandled exception. | Enforced unique compound index on `{"emp_code": 1, "date": 1}`, relying on atomic MongoDB insertion and catching `DuplicateKeyError` to return 409. |
| 10 | `punch_in()` (lines 102-103) | Timestamp parsing and date calculation defects: (1) Does not truncate instants to whole seconds (R1). (2) Derives date from server's local machine timezone instead of IST. (3) Does not handle overnight shift rule where punch-in before `shift_end` belongs to the previous calendar day. | Punch-in at 01:30 IST for a 22:00-06:00 shift assigns current calendar date instead of yesterday's date. Timestamps with millisecond fractions are not truncated. | Validated epoch ms range; converted to IST; mapped overnight shift punches before `shift_end` to previous date; truncated seconds (`ms // 1000 * 1000`). |
| 11 | `punch_in()` (lines 118-121) | Response structure violates API contract: attaches MongoDB internal `id: str(inserted_id)` and returns unformatted datetime objects. | Response JSON contains `"id"` and ISO string timestamps, which violates the `AttendanceRecord` schema. | Removed `"id"`; serialized all timestamps (`punch_in`, `punch_out`, history) to epoch milliseconds. |
| 12 | `list_attendance()` (lines 133-150) | In-memory pagination and sorting: calls `list(db.attendance_logs.find(q))` loading entire collection into RAM, sorts with Python lambda, and slices in memory. Exposes internal `id`. Does not validate `date_from > date_to`. | Querying against a 100,000 document collection causes high latency and memory exhaustion. `date_from > date_to` returns 200 instead of 422. Items contain internal `"id"`. | Implemented indexed filtering, sorting `[("date", -1), ("emp_code", 1)]`, skip, and limit directly inside MongoDB; added `date_from <= date_to` validation; stripped `_id`. |

### What was examined and decided was NOT a defect
1. **Business key `emp_code` instead of ObjectId:** Using `emp_code` as the primary identifier across API endpoints rather than MongoDB's `_id` is an intentional architectural requirement specified in `DATA_MODEL.md`.
2. **Nullable / Defaulted fields:** Initializing `punch_out` and `work_hours` as `null`, `overtime_minutes` as 0, and `half_day` as `false` on punch-in accurately reflects the data model state for open records.
3. **Internal BSON Dates vs. External Epoch Milliseconds:** Storing dates as BSON UTC datetimes in MongoDB while accepting and returning integer epoch milliseconds at the API boundary conforms to the API contract.
